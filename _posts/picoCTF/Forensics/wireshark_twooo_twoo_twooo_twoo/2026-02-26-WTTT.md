## Initial steps

Just like the [previous challenge](https://robinva-uit.github.io/posts/WSDDDD1/), I inputted the provided `.pcapng` file in Wireshark, and [opened the hierachy table](https://robinva-uit.github.io/posts/WSDDDD1/#:~:text=Statistics%20(on%20the%20menu%20bar)%20%2D%3E%20Protocol%20Hierachy):

![hierachy](/assets/img/picoCTF/Forensics/wireshark_twooo_twoo_twooo_twoo/hierachy.png)

There were 16.6% packets that had HTTP. We could [extract a lot of human-readdable information](https://robinva-uit.github.io/posts/WSDDDD1/#:~:text=In%20fact%2C%20HTTP%20packets%20can%20contain%20plaintext%2C%20which%20is%20at%20the%20other%20end%20of%20the%20spectrum%20compared%20to%20HTTPS%20(encrypted%20HTTP).%20For%20that%20reason%2C%20I%20focused%20on%20these%20packets%20first.) from these packets.

[Filtering the list with keyword `http` in the filter box and clicking the `Info` column](https://robinva-uit.github.io/posts/WSDDDD1/#:~:text=I%20typed%20http,GET%20ones%20first.), this was the initial look:

![filter](/assets/img/picoCTF/Forensics/wireshark_twooo_twoo_twooo_twoo/filter.png)

There were so many GET packets. The source was `192.168.38.104`, and the destination was `18.217.1.57`. The source was requesting the file `flag` a lot of times.

Scrolling down, I finally saw the response packets:

![response](/assets/img/picoCTF/Forensics/wireshark_twooo_twoo_twooo_twoo/response.png)

I checked the first packet, and it said: "*The official Red's Shrimp and Herring website is still under construction. Please check back later!*":

![redshrimp](/assets/img/picoCTF/Forensics/wireshark_twooo_twoo_twooo_twoo/redshrimp.png)

I suspected `18.217.1.57` was the IP address of the mentioned "*Red's Shrimp and Herring*" website.

Next, I decided to take a look at other response packets as well. However, all I got were red herrings (fake flags):

![red1](/assets/img/picoCTF/Forensics/wireshark_twooo_twoo_twooo_twoo/red1.png)

![red2](/assets/img/picoCTF/Forensics/wireshark_twooo_twoo_twooo_twoo/red2.png)

There were still many more fake flags below.

I continued to scroll, and a red packet appeared to have a Base64 code, I presumed.

![red-packet](/assets/img/picoCTF/Forensics/wireshark_twooo_twoo_twooo_twoo/red-packet.png)

![b64](/assets/img/picoCTF/Forensics/wireshark_twooo_twoo_twooo_twoo/b64.png)

After [following the packet](https://robinva-uit.github.io/posts/WSDDDD1/#:~:text=We%20have%20two,HTTP%20stream.), I copied the code and pasted it on CyberChef's Base64 decoder. Unfortunately, the result was a garbage text:

![b64-fake](/assets/img/picoCTF/Forensics/wireshark_twooo_twoo_twooo_twoo/b64_fake.png)

The rest of HTTP packets didn't have much valuable intel for me.

For that reason and from the analysis that I made, I decided to specifically analyze packets sent from `18.217.1.57`. The "*Red's Shrimp and Herring*" website seemed to be the most outstanding hint out there.

## Solution paths

If you wish to see only packets that `18.217.1.57` sent, just type this in the filter box:

`ip.src == 18.217.1.57`

Then, make sure to click the "Time" column to sort the list by time order.

After flitering, I started exploring the list. Suddenly, a suspicious DNS (Domain Name System) packet appeared out of no where. Just look at the subdomain:

![aha](/assets/img/picoCTF/Forensics/wireshark_twooo_twoo_twooo_twoo/aha.png)

The code before `..reddshrimpandherring.com` was `cGljb0NU`. I randomly put this in CyberChef's Base64 decoder, and the result was surprising:

![first_part](/assets/img/picoCTF/Forensics/wireshark_twooo_twoo_twooo_twoo/first_part.png)

It was "picoCT" in "picoCTF"! I assumed that in the upcoming DNS packets, the Base64 flag parts were hidden there as well. I added one more filter in the filter box to show only DNS from `18.217.1.57`:

`ip.src == 18.217.1.57 && dns`

![parts](/assets/img/picoCTF/Forensics/wireshark_twooo_twoo_twooo_twoo/parts.png)

And there you go: all flag parts were revealed. [Follow](https://robinva-uit.github.io/posts/WSDDDD1/#:~:text=We%20have%20two,HTTP%20stream.) each distinctive packet, paste them in your Base64 decoder, and you will eventually get the flag.

![flag](/assets/img/picoCTF/Forensics/wireshark_twooo_twoo_twooo_twoo/flag.png)

## Flag
`picoCTF{dns_3xf1l_ftw_deadbeef}`

## Key takeaways/Lessons learned

* **DNS exfiltration**: In this challenge, the attacker sent the collected data by putting it in the subdomain of their own website, and via Internet and DNS servers (DNS query), asking the system (DNS resolvers) to resolve the domain. The attacker then read the log of his website and got the info.
